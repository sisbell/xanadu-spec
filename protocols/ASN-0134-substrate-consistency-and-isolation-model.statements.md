## Definition — Execution

By `SequentialTransitionAxiom` the substrate's behaviour under any number of agents is a single sequence of states

`𝔼 :  Σ₀ → Σ₁ → Σ₂ → ⋯`

in which each `Σ_i → Σ_{i+1}` is one atomic step `σ_i` drawn from the step vocabulary of ASN-0128's gated relation, `K = {K.σ, K.α, K.λ_sh}` — that is `→_sh ≡ K.σ ∪ K.α ∪ K.λ_sh`: document registration, content allocation, and gated link/tuple emission. We anchor the sequence at its initial state, `Σ₀ = Σ_init`. Write `idx(σ) = i` for a step's position. We index states by their position in this one order; `Σ_i →* Σ_j` holds exactly when `i ≤ j`.

## Definition — FrontierPopulation

For `S ∈ {s_C, s_L}` write `dom_S(Σ)` for `dom(Σ.C)` when `S = s_C` and `dom(Σ.L)` when `S = s_L`, and define the home's `S`-population and `S`-frontier index

`P_S(d, Σ) = {a ∈ dom_S(Σ) : origin(a) = d}`,  `φ_S(d, Σ) = |P_S(d, Σ)|`.

By `ChainMembershipForOrigin` (ASN-0093), `P_S(d, Σ)` is a *contiguous initial segment* of the chain `A_S(d)`, so `φ_S(d, Σ)` is the count of already-emitted slots and the next emission lands at chain slot `φ_S(d, Σ)`, advancing the count by one.

## Definition — BatchContiguity

A *batch* is a finite collection of operations issued as one logical act by one agent or one rule firing. Its constituent steps land at some indices `i₁ < i₂ < ⋯ < i_m` in `𝔼`. Call the batch **contiguous** when `{i₁,…,i_m} = {i₁, i₁+1, …, i₁+m−1}`, i.e. no foreign step interleaves; otherwise **split**.

## Definition — MultiReadVerdict

With no whole-state read available, a `p`-read verdict is realized as

`Q = g(c₁(Σ_{r₁}), …, c_p(Σ_{r_p}))`

for a combining function `g` over the `p` *bounded-access constituents* `c₁, …, c_p`, each `c_i` a single-state read taken at its own read index `r_i`, the indices non-decreasing (`r₁ ≤ ⋯ ≤ r_p`, since zero-step reads do not advance `𝔼`). The constituents include both active-view reads `Observe_{K_i}` and per-home frontier descents `f_{d_i}`.

## Definition — QAffectingStep

Define a writer step to be **`Q`-affecting**, relative to a read window, when it changes the value of some constituent `c_i` whose read has not yet been taken — i.e. `c_i` evaluated just before the step differs from `c_i` just after, for some such `i`. The quantifier ranges over *every* constituent, frontier descents included: a step that advances a not-yet-read frontier `f_{d_i}` *is* `Q`-affecting even when it disturbs no active view.

## A0 — StepAtomicity (AXIOM, axiom)

There is no state strictly between `Σ_i` and `Σ_{i+1}`. The states an observer can ever name are exactly `{Σ_k : k ∈ 𝔼}`.

## A1 — Realization (AXIOM, axiom)

A *single* state-changing operation — one not issued as a batch — is realized as *exactly one* atomic step, at a unique index; distinct such operations occupy distinct indices. (A multi-step batch is many steps, not one operation — A5.) An operation that leaves the state unchanged is realized as *zero* steps — it reads and returns, committing no step — and this happens in four ways: a *read-only query* — an `Observe_K`, or any of ASN-0128's behavioral *reads* (D1–D4; BH1–BH3; BH4's `age`/`stale` — but not BH4's `retract_stale`, a multi-step batch by A5), each committing no `→_sh` step; an idempotent `Emit_K` hit; the hit branch of a `Nullify_Binary`; and a *rejected* call, one whose precondition fails at the state it is evaluated against — e.g., a gate, `P0`, or `P-tgt` failure (ASN-0128 S3, I6). The first three return a value read off the state; the fourth returns failure and adjoins nothing. These four are the *single-operation* zero-step cases; an empty `m = 0` fire (a `retract_stale` over an empty stale set, A5) is the fifth, degenerate-batch zero-step case.

Whether a *would-be* state-changing operation realizes as one step or is *rejected to zero* can itself depend on the state it meets, hence on the linearization: a `Nullify_Binary` whose `P-tgt` holds at one index and fails at another fires in the first case and is rejected in the second. An operation's very presence in the realized step set can be order-dependent.

## A2 — LinearizationPoint (DEF, function)

A state-changing operation `op` realized as step `σ` has linearization point `lin(op) = idx(σ)`; its *entire* effect is the single transition `Σ_{lin(op)} → Σ_{lin(op)+1}`. A zero-step operation realized as a *single bounded access* has `lin(op)` equal to the one index it reads; its effect on state is the identity. A zero-step operation realized as *several* bounded accesses — a `stale` enumeration or a cross-type join, which read multiple committed states at distinct indices (§8) — has no single read index and hence no single `lin`; its soundness is the province of V0/V2 (§8), not of any one linearization point. Its effect on state is likewise the identity. (So A1 classes both kinds as zero-step; A2 hands a single `lin` only to the single-access kind; §8 governs the rest.)

## A3 — SnapshotRead (AXIOM, axiom)

Two readings must be held apart. *Abstractly*, `Observe_K(Σ)` is — by its ASN-0086 definition as a function of `Σ` — a total function of the single state `Σ`, a property of the definition that holds irrespective of concurrency. *Realized*, the `Observe` a concurrent implementation performs is a *bounded access* whose internal sub-reads — for `Observe_K`, the `A_K = L_K ∖ nullified` computation over the link store and the retraction slice — each land on some committed state of `𝔼`. That they land on *one* committed state `Σ_k`, so that the realized read returns `Observe_K(Σ_k)` — a total function of the single `Σ_k`, depending on no other state — is *not* delivered by the read's zero-step character (which secures only that it advances `𝔼` by no step of its own, A1); it is exactly MIC clause 4's obligation, the single-state realization of a bounded access. Absent clause 4 the sub-reads may straddle a commit and compound two committed states into one read.

## A4 — NoTornStep (LEMMA, lemma)

No `Observe` witnesses a partial step. For an `Observe` at index `k` and a state-changing `op` with `lin(op) = i`: if `k ≤ i` the `Observe` sees none of `op`'s effect; if `k ≥ i+1` it sees all of it. There is no third case.

*Proof.* `op`'s effect is precisely the transition `Σ_i → Σ_{i+1}` (A2). The realized `Observe` reads a single committed state `Σ_k` — the index clause 4 pins it to (A3's realized register) — which is either at-or-before `Σ_i` (`k ≤ i`, effect absent) or at-or-after `Σ_{i+1}` (`k ≥ i+1`, effect present). The excluded middle — a state strictly between `Σ_i` and `Σ_{i+1}` — does not exist (A0). ∎

## A5 — NoBatchIsolation (LEMMA, lemma)

A multi-step batch (`m ≥ 2`) is not atomic, in two independent senses. *(Partial visibility — always, modulo the read surface.)* For *any* batch, contiguous or split, the interior states *exist*, and each carries a strict, non-empty *prefix* of the batch's own effects: the batch's first atom is committed at `Σ_{i₁+1}` while its last is not committed until `Σ_{i_m+1}`, and a reader may land at any interior index `k` with `i₁ < k ≤ i_m` (A0, A3). Whether that prefix is *read-witnessed* turns on the batch's subspace, because §8 fixes the read surface as link-store reads (active views `Observe_K`, link-subspace frontier descents) with no read over content population: a *link-store* batch — a `retract_stale` issuing its `Nullify_Binary`s — has each partial effect visible to an `Observe_K` over the active slice `A_K`, so an interior read returns some events retracted and others not; a *content* run (one `K.α` per atom) is non-atomic only *structurally* — its mid-batch state exists and is canonical (A6), but its prefix is witnessed by no read the note models. This needs no foreign step — it follows from `m ≥ 2` alone. *(Foreign interleaving — when split.)* If the batch is *additionally* split, some foreign step at index `j` with `i₁ ≤ j < i_m` interleaves, so an interior `Σ_{j+1}` also carries effects *not* belonging to the batch. Either way the batch's partial effects are observable; the substrate's all-or-nothing guarantee stops at the single step (A0). The *degenerate* batch sizes are atomic after all — an `m = 1` fire is a single step, indivisible by A0 exactly as a lone operation is, and an `m = 0` fire (an empty `retract_stale`) commits no step, so there is no interior index to land on and the partial-visibility argument has no foothold. Non-atomicity is a strictly `m ≥ 2` phenomenon.

## A6 — CanonicalState (LEMMA, lemma)

Call a state *structurally canonical* iff every per-state invariant of the `→_sh` stack — every invariant that is a predicate of a single state — holds at it. *Every* state on `𝔼` is `→_sh*`-reachable — the prefix `Σ₀ → ⋯ → Σ_k` witnesses `Σ_init →_sh* Σ_k` (§1) — and reachability is exactly the hypothesis the foundations' transfer lemmas require, so `B2`/`RP-a` carry *every* per-state stack invariant to `𝔼`'s states. Hence *every* `Σ_k` on `𝔼` is structurally canonical. The one external constant any such invariant reads against is registry-fixity's `R₀ := Σ_init.registry`, the construction-fixed initial record (ASN-0128 `R-VAL`), single-state content of ASN-0126's `P1` / ASN-0128's `R1`. Canonicity is genuinely single-state: each conjunct is a predicate of `Σ_k`'s own components, checkable against `Σ_k` and the external constant `R₀` alone, never against another state.

The stack's *transition* invariants — append-only monotonicity and value-immutability `C0` (content) and `L12` (link), and ASN-0093's document-set monotonicity `M1` (`(A Σ → Σ' :: dom(M) ⊆ dom(M'))`, no step removes a registered document) — have the form `(A Σ → Σ' :: …)` with no single-state shadow, so a companion *transition clause* carries them on the same reachability base: for every `k ≥ 1`, the step `Σ_{k-1} → Σ_k` on `𝔼` preserves `C0`, `L12`, and `M1`, by `B2`'s transition clause and `RP-b`. The chain-contiguity members — `ChainMembershipForOrigin`, with `L-ContiguousPrefix` its link-store form — hold at every state of `𝔼` by reachability. Their *preservation* under any interleaving is the earliest model-intrinsic result: the allocator deposits only at the next sibling of a home's current chain-maximum (`inc(max,·)`; ASN-0093 `FirstEmission`/`SubsequentEmissionFreshness`), no step ever removes a slot (`C0`/`L12`), and a step into any other home or subspace leaves this home's population untouched — so a gapless initial segment stays a gapless initial segment step by step, under *any* interleaving and with no appeal to per-home order.

## A7 — CommitBeforeAcknowledge (AXIOM, axiom)

For the linearization point of A2 to be presentable to a concurrent client, an operation's response/return value must be produced only at or after `lin(op)`. An acknowledgment emitted before the committing step is unsound: it lets a caller act on an effect that is not yet (and may never be) in the order.

## H0 — FrontierDiscipline (LEMMA, lemma)

Along `𝔼`, for fixed `(d, S)`, `φ_S(d, ·)` is non-decreasing, increases by exactly one at each `S`-allocation to `d`, and is left unchanged by every other step.

*Proof.* An `S`-allocation to `d` adjoins one fresh address with `origin = d` and subspace `S` (ASN-0093 K.α / ASN-0128 K.λ_sh effect), so `|P_S(d, ·)|` rises by one. Any other step is either a `K.σ`, which registers a document and frames both stores (`C' = C ∧ L' = L`, ASN-0093 K.σ), leaving every `dom_S` fixed; or an allocation into a different `(d', S') ≠ (d, S)`, which adjoins one fresh address `a'` with `origin(a') = d'` to store `dom_{S'}` and frames everything else. That `a'` falls outside `P_S(d, ·) = {a ∈ dom_S(·) : origin(a) = d}` needs no disjointness lemma — only the set's own two filters, store-membership in `dom_S` and `origin = d`, against the fact that `(d', S') ≠ (d, S)` diverges along at least one axis. *If `S' ≠ S`* (whether or not `d' = d`): the step writes only `dom_{S'}` and leaves `dom_S` framed, so `P_S(d, ·) ⊆ dom_S` is untouched outright. *If `S' = S`* (which forces `d' ≠ d`): the step does add `a'` to `dom_S`, but `origin(a') = d' ≠ d` fails the `origin = d` filter, and — `origin` being a structural projection fixed per address and `dom_S` append-only — no prior member departs either, so `P_S(d, ·)` is again unchanged. These two cases exhaust `(d', S') ≠ (d, S)`; the cross-home, cross-subspace pair (`d' ≠ d ∧ S' ≠ S`) falls under the first. In every case `P_S(d, ·)` is unchanged. ∎

## H1 — CrossHomeIndependence (LEMMA, lemma)

Two allocation steps into distinct `(d, S) ≠ (d', S')` *commute*: neither reads or writes state the other touches, and applying them in either order yields the same state.

*Proof.* The first reads `φ_S(d,·)` and writes one address on chain `A_S(d)`; the second reads `φ_{S'}(d',·)` and writes on `A_{S'}(d')`. We show the two chains are disjoint as address sets, across the two axes along which `(d, S) ≠ (d', S')` can differ. *If `d ≠ d'`:* we argue by *origin*, because origin settles the cross-document case uniformly across subspaces — including the cross-document, cross-subspace `S ≠ S'` pair that `CrossDocumentDisjointness`'s single-`·` statement leaves unnamed. The address the first step deposits joins `P_S(d,·)`, defined by the `origin = d` filter, so it carries `origin = d`; the second's deposit carries `origin = d'`. Since `origin` is a structural projection fixed per address (H0) — a function of the address alone — `a = a'` would force `d = origin(a) = origin(a') = d'`, contradicting `d ≠ d'`. Hence the two deposits are distinct and `A_S(d) ∩ A_{S'}(d') = ∅` *regardless of subspace*. *If `d = d'`* (which forces `S ≠ S'`): the two chains share an origin, so origin cannot separate them; instead the sibling-subspace anchors `[d.0.s_C]` and `[d.0.s_L]` diverge at the subspace digit, so by T10 (PartitionIndependence) the chains are disjoint — `DisjointSubAllocatorChains`. In every case the deposits are distinct and the chains disjoint. By H0 neither step changes the other's frontier population. So each step's precondition (its frontier value) and effect (its deposited key) are on state disjoint from the other's; they commute. ∎

## H2 — SameHomeConflict (LEMMA, lemma)

Two allocation steps into the *same* `(d, S)` conflict: each reads `φ_S(d,·)`, and the first to commit increments it (H0), so the two *cannot* read the same frontier value without colliding. If both read frontier `φ`, both deposit at chain slot `φ` — the *same address* — violating freshness.

*Proof.* Two emissions into `(d, S)` against a common pre-state `Σ_pre` read the same population `P_S(d, Σ_pre)`, and the emission rule is a function of that population, so they compute the same deposit address — in *either* of its two branches.

*Interior case* (`P_S(d, Σ_pre) ≠ ∅`): `SubsequentEmissionFreshness` gives `a = inc(a_prev, 0)` with `a_prev = max P_S(d, Σ_pre)`; both read the same `a_prev`, hence compute the same `a`.

*First-emission boundary* (`P_S(d, Σ_pre) = ∅`): here `max P_S(d, Σ_pre) = max ∅` is undefined and the subsequent rule does not apply. Instead both emissions satisfy ASN-0093's *first-emission* predicate `{a' : origin(a') = d} = ∅` and both compute the determinate first slot `a = [d.0.S.1]` (`FirstEmission`). This is the race for the *first* allocation into a fresh home, and it collides just as squarely.

In either case the two compute one address; whichever commits first deposits it, and the second's freshness precondition — `a ∉ dom_S`, discharged in the interior case by `SubsequentEmissionFreshness` and at the boundary by `FirstEmissionFreshness` — then fails. The conflict is identical at the boundary and in the interior. ∎

## H3 — RegistrationIndependence (LEMMA, lemma)

Under the shared-frontier conditional of §4, a `K.σ` registering `d_new` *commutes* with every `→_sh` step except two `≺`-comparable ones it must be sequenced against: an allocation into `d_new` itself, and a same-account `K.σ` racing it for the same document-frontier slot. *(a)* Against an allocation `K.α`/`K.λ_sh` into a home `d ≠ d_new`: `K.σ` writes only `dom(M)` (adjoining `d_new`) and frames the stores (`C' = C ∧ L' = L`), while the allocation writes only `dom(C)`/`dom(L)` and frames `M` — disjoint components — and each precondition survives the other (the allocation's `d ∈ dom(M)` under `dom(M)`'s growth, `K.σ`'s `d_new ∉ dom(M)` under the allocation's frame on `M`). *(b)* Against a `K.σ` registering `d'_new ≠ d_new`: the two targets being distinct, each adjoins a distinct fresh document and frames the stores, and `d'_new ≠ d_new` preserves both freshness preconditions across the swap. The two *non*-commuting pairs are `K.σ(d_new)` against an allocation into `d_new`, whose `d_new ∈ dom(M)` holds only *after* the registration (the register-before-allocate dependency), and a same-account `K.σ` pair reading one document frontier (the account-tier H2 collision); both `≺`-comparable, neither ever transposed.

*Proof.* The two cases commute for *different* structural reasons, and folding them together would misdescribe (b). *(a)* is genuinely a disjoint-write commutation — the registration analog of H1's disjoint-state argument: `K.σ` writes only `dom(M)` while the allocation writes only a store and frames `M`, so the two touch disjoint components, each precondition surviving the other (as the statement details). Here `dom(M)` plays the role a sub-allocator chain plays in H1 — a component one step writes and the other does not. *(b)* is *not* a disjoint-write: both `K.σ` steps *read* `dom(M)` (the precondition `d_new ∉ dom(M)`) *and write* `dom(M)` (inserting their target), sharing read-and-write access to the *one* component `dom(M)` — there is no second chain to separate them the way H1 has two. They commute instead by *distinct-element non-interference*: a membership-test-and-insert of `d_new` and one of `d'_new` do not interfere precisely because the targets are distinct (the case hypothesis `d'_new ≠ d_new`), so each step's `dom(M)`-read verdict and inserted element are unchanged by the other's insertion, and both freshness preconditions survive the swap. ∎

## W0 — MonotonicityStepLocal (INV, predicate)

Append-only monotonicity and value-immutability — `C0` (ContentImmutability) and `L12` (LinkImmutability), together with document-set monotonicity (ASN-0093's `M1`, ArrangementMonotonicity, `dom(M) ⊆ dom(M')`) — are *model-intrinsic*: their preservation across every step of `𝔼` (A6's transition clause) needs *only* per-step atomicity (A0) and no per-home ordering. Under any interleaving of atomic steps, `dom(C)`, `dom(L)`, and `dom(M)` only grow and existing values never change.

## W1 — ChainContiguityStructural (INV, predicate)

Dense chain contiguity — `ChainMembershipForOrigin`'s gapless initial segment `P_S(d, ·) ⊆ A_S(d)`, with `L-ContiguousPrefix` its link-store form — is *model-intrinsic* (its preservation under every valid step carried by A6). The failure mode without per-home serialization is therefore a *collision*, never a hole: hole-impossibility is A6's, carried by the `inc(max,·)` allocator's gaplessness preservation under any interleaving. A stale frontier read runs the *other* way, to a lower already-filled slot, so two same-home emissions reading one frontier compute the *same* address (H2) and one is rejected to zero (A1) — shrinking the realized population but never perforating it. What per-home serialization buys is thus not contiguity but same-home *uniqueness* (H2): that two concurrently-proposed same-home allocations both succeed at distinct slots rather than colliding. Gregory's evidence, read precisely, locates the genuine dependence on a *different* allocator: a counter-style allocator handing out increasing indices without consulting the population "would preserve uniqueness and global monotonicity but lose contiguity whenever allocations interleave" — but that allocator is *not* `inc(max,0)`, which couples deposit to population, and §1 commits `𝔼` to the `inc(max,0)` stack that excludes it. Under that stack contiguity is structural; the one genuinely serialization-borne contiguity claim is W2's run contiguity, not this one.

## W2 — RunContiguityCritical (LEMMA, lemma)

A multi-atom content run for a definition in home `d` (a batch of `K.α` steps into `(d, s_C)`) occupies a contiguous block of `A_{s_C}(d)` iff no foreign allocation into `(d, s_C)` is interleaved between the run's first and last step. This is a *per-`(home, subspace)` critical section spanning the run* — strictly stronger than the per-step per-home serialization that secures same-home uniqueness (H2), strictly weaker than any cross-home exclusion.

*Proof.* By H0 each `s_C`-allocation to `d` lands at the then-current frontier and advances it by one. If the run's `m` steps are the only `s_C`-allocations to `d` in the index interval they span, they land at consecutive slots `φ, φ+1, …, φ+m−1`: a contiguous block. If a foreign `s_C`-allocation to `d` lands at some interior index, it consumes a frontier slot between two of the run's atoms, and the run's remaining atoms land *past* it — the run's slots are `{φ, …}` with a foreign slot embedded, no longer an interval. By H1, a foreign allocation into any *other* `(d', S')` leaves `φ_{s_C}(d, ·)` fixed and cannot break the run. ∎

## W3 — ActiveSliceStepLocal (INV, predicate)

The relationship between the audit slice `L_K` (every type-`K` tuple ever emitted) and the active subset `A_K` is model-intrinsic, and definitionally so: `A_K = L_K ∖ nullified` *by definition* (ASN-0086 `ActiveSubset`), so both are pure functions of the single state read and an `Observe` at index `k` computes them from `Σ_k` mutually consistently (A3) — coherent at every state by construction, under any interleaving. Nullification only grows `nullified` (R6a, RetractionStability), never rewriting or perforating the relation. Needs only A0.

## W4 — RegistryRaceFree (INV, predicate)

The registry is immutable across all runtime steps (`RegistryInvariance` / P1 of ASN-0126, R1 of ASN-0128: `Σ.registry = Σ_init.registry` at every reachable state). No step in `K` writes it. Hence the question "may two agents writing the same registry interleave?" has *no realization*: registry writes are confined to the single, pre-execution construction of `Σ_init` (`R-VAL`), which is not a step of `𝔼`. Runtime registry access is pure read of an immutable structure — always consistent, never torn, by definition. The write-write race is *vacuously absent*.

## G0 — Serializability (THEOREM, lemma)

*Client model (the pipelining client above):* per-agent *program order* is neither modeled nor preserved. The substrate realizes a single total order of atomic steps (`SequentialTransitionAxiom`), each operation appearing atomic at its `lin`; so every execution is *serializable* — equivalent to the serial order `𝔼`. The order is logical (a per-home arrival sequencing), carrying no global temporal coordinate that observers must agree on — Nelson is emphatic that "time is not included in the tumbler; time is kept track of separately," so the address space refuses to encode the global timeline a stronger, *linearizable* guarantee would demand. We name this *serializability*, and pointedly *not* *sequential consistency* — but the conclusion takes two steps that must be kept apart, because the first does not reach it alone. *(1) The substrate does not enforce program order.* An agent's operations into *distinct* homes are `≺`-incomparable (§4), and the linearization resolves them without regard to which the agent issued first. This by itself is *no* SC violation: distinct-home operations commute (H1, G1(ii)), so reordering them is observationally benign — the program-order serial order reaches the very same state, and *that* execution is sequentially consistent. Breaking SC needs an execution whose observations *no* program-order-respecting serial order can reproduce. *(2) A third-party observer exhibits one.* Let agent P emit, in program order, `A` into home `α` then `B` into home `β` (`α ≠ β`); pipelining leaves the two `≺`-incomparable, so the linearization may commit `B` before `A` (H1: both orders are valid and reach the same state), opening a real window in which `B` is present and `A` is absent. Let observer Q, in its own program order, `Observe` `β` then `α` at two indices inside that window: Q sees `B` *present*, then `A` *absent*. Any SC serial order `S` must respect both program orders — `A <_S B` for P, `(read β) <_S (read α)` for Q — and reproduce Q's reads — `B <_S (read β)` (B seen present) and `(read α) <_S A` (A seen absent). Together these force the cycle `A <_S B <_S (read β) <_S (read α) <_S A`, so no such `S` exists: the execution is *not* sequentially consistent. This coexists with the *linearizability* §3 grants under A7 — but the coexistence is *not* a breach of the textbook theorem Lin⟹SC, and seeing why forces us to be explicit that the note's "linearizability" is **real-time-precedence-only**, hence *strictly weaker* than the textbook notion. Textbook linearizability asks its witnessing serial order to do two things: respect real-time precedence between non-overlapping operations, *and* — through its equivalence clause, that the order reproduce each process's own subhistory — respect each process's *program* order. That second, program-order conjunct is exactly what lets textbook linearizability imply SC. We keep only the first: A7 pins a linearization point that orders a response before any strictly-later invocation, and constrains nothing about one agent's internally-overlapping issues. So the note's notion does *not* imply SC — and no theorem is contradicted, because Lin⟹SC assumes *sequential-process* clients, whose program order *is* their real-time order (each operation issued only after the prior's response, so no two overlap); under that hypothesis the real-time conjunct already delivers the program-order conjunct, and SC follows. A *pipelining* client withdraws the hypothesis: P issues B before A's response returns, so A and B overlap and program order ⊄ real-time order on that pair. This is the seam, and it forces a reconciliation we state plainly, because the two halves of G0 read P's pair *differently, and must*: the SC witness treats A,B as *program-ordered* — it must, to force `A <_S B` and close its cycle — while the linearizability claim treats the *same* pair as *unordered*, since they overlap in real time and real-time-only linearizability fixes no serial order between overlapping operations. Pipelining is precisely where program order and real-time order diverge, and that divergence — not any failure of Lin⟹SC, whose sequential-process premise pipelining denies — is what carries "real-time-linearizable ∧ ¬SC." A *sequential* client recovers SC by its own acknowledgment discipline (issuing each operation after the prior's response), not by any substrate promise. The substrate that serves both client styles guarantees only serializability.

## G-PO — PartialScheduleModel (DEF, definition)

A *schedule* over a reachable start state `Σ` is a finite set `O` of allocation steps (`K.α`, `K.λ_sh`) into homes already registered at `Σ` — no `K.σ` is scheduled *in this base model*, the register-before-allocate dependency discharged in advance per this section's scoping; `H3` below lifts the result to schedules that do register documents — equipped with a partial order `≺` — the order the implementation *forces* — such that for every `(d, S)` the `S`-allocations to `d` in `O` are pairwise `≺`-comparable (*per-home serialization*), while steps into distinct `(d, S) ≠ (d', S')` need not be. A *linearization* of `(O, ≺)` is any total order extending `≺`; run from `Σ`, each linearization is one execution `𝔼`. The total order of §1 is the special case in which `≺` is itself total.

## G1 — PerHomeSerializabilitySuffices (THEOREM, lemma)

Let `(O, ≺)` be any per-home-serialized schedule over a reachable `Σ`. Then (i) *every* linearization of `(O, ≺)` is a valid execution preserving every per-state invariant at every state and every allocation invariant in its final state; and (ii) all linearizations are *confluent* — they reach one and the same final state, with the same address at every chain slot of every home. The cross-home order is free to vary, and no invariant and no committed address depends on how a linearization resolves it.

*Proof.* (i) We secure *validity* first, and read the per-state package off the reachability it yields — for A6 (reachable ⟹ canonical) cannot license per-state invariants until the linearization's steps are known to be valid `→_sh` steps. The one precondition a reordering can disturb is an allocating step's *frontier-freshness*; every other precondition is reordering-*invariant*. Frontier-freshness is a per-home matter: per-home comparability totally orders `(d, S)`'s allocations, so by H0 each reads the frontier its predecessor left and lands at the next slot — its deposit fresh and collision-free — and by H1 no cross-`(d, S)` step disturbs that frontier wherever the linearization places it. The reordering-invariant remainder holds at every position regardless of order: a `K.λ_sh` gate reads only data no transposition moves — `Sh-conf(K, F, G)` the presented value `(F, G)` and the registry-fixed `shape(K)` (ASN-0126 `P4`, ShConfStateIndependence), arity-3 the value alone, and K's registration the registry keys — all immutable across runtime steps (W4 / ASN-0128 `R1`); and every allocation's home precondition `d ∈ dom(M)` survives once met, since `G-PO` schedules only into homes already registered at `Σ` and ASN-0093's `M1` (document-set monotonicity, named in A6's transition clause) admits no document removal, so `d` stays in `dom(M)` at every position. Each step's precondition is thus met at its position, so the linearization is a valid execution — whence each of its states is `→_sh*`-reachable from `Σ`, the prefix reaching it its witness (§1). *Now* — reachability in hand — A6 applies, scoped exactly as §5 requires, carrying every conjunct of its per-state package (the chain-contiguity members included) to every state of every linearization. The final-state allocation invariant G1(i) *separately* promises — same-home uniqueness (H2) — is the one thing per-home comparability buys: two same-`(d, S)` allocations both land fresh rather than lose one to a collision. The split this rests on — contiguity model-intrinsic and free, same-home uniqueness serialization-borne (H2) — is the one A6 established. (ii) Any two linearizations of a finite partial order differ by a finite sequence of transpositions of adjacent `≺`-incomparable steps; incomparable steps here are into distinct `(d, S)` (per-home comparability makes same-`(d, S)` steps comparable), so each transposed pair commutes (H1), leaving the surrounding states and every committed address unchanged. Confluence to a single final state follows, and ASN-0093's sequential results, holding along any one linearization, thereby describe them all. ∎

## G2 — SurfaceEmitDivergence (LEMMA, lemma)

I1a's *literal* clause calls a derivation `K`-surface-emitted iff every `L_K`-growing step is "the deposit branch of an `Emit_K` invocation"; the *operative* notion its induction actually uses asks more — each such deposit must be a *miss evaluated at that step's own pre-state* ("at the pre-state its I0-class had no active member"). Under ASN-0128's sequential operation→step identification the two coincide, an operation's dedup-read input state *being* its step's pre-state. A concurrent realization in which an emit's dedup-read and its deposit's pre-state diverge breaks the coincidence: the deposit is a miss against the *stale* state its dedup-read saw yet a hit against its own later pre-state, so the derivation is `K`-surface-emitted under the literal clause but *not* in the operative sense, I1a's induction fails at that deposit, and the `idem = ⊤` duplicate stands.

## V0 — VerdictSnapshotLocal (LEMMA, lemma)

A verdict obtained by a *single bounded access* — a single `Observe_K` (a predicate on one type's active view), or equally an `age` read of one home's single-state frontier `f_d` — is `Q(Σ_r)` for the one index `r` that access reads (A3's realized register, under clause 4): it is a sound statement *about the one state* `Σ_r`, and about no `Σ_{r'}` with `r' ≠ r`. The discriminator is *access count*, not type-confinement: what makes the verdict snapshot-local is that its lone access lands on one index, whether that access reads a type's active view or a home's cross-type frontier. That `age` qualifies is the one case needing an argument: `age(a) = f_d^Σ − 1 − j` reads not a type's active view but the *home* `d = home(a)`'s link-subspace frontier `f_d^Σ`, which interleaves *every* link type homed at `d` (BH4) — *not* an `Observe_K`-grade read. Yet it is single-*index*: by `L-ContiguousPrefix` (ASN-0086) the home's link population is a contiguous initial segment of the *one* chain `chain_d`, so `f_d^Σ` is simply its length, recovered in one bounded access over that home's link subspace (Gregory's `findpreviousisagr` — a single bounded granfilade descent under the home's link-subspace upper bound), never by unioning per-type views at drifting indices, of which there are none. So `age` is a *home-relative single-snapshot* read — one index, free under clause 4 like the single-type reads. Because every state on `𝔼` is structurally canonical (A6), `Σ_r` is always a coherent referent — there is always a well-defined "single frozen view" to evaluate `Q` against.

## V1 — VerdictRetrospective (INV, predicate)

A verdict `Q(Σ_r)` is retrospective: it asserts `Q` of `Σ_r` and of nothing later. For `r' > r`, `Q(Σ_{r'})` may differ — any step at index `j` with `r ≤ j < r'` may falsify `Q`. Extending a verdict from "held at `r`" to "holds through `r'`" requires an *additional* hypothesis the substrate does not supply: that no `Q`-falsifying step is linearized in the interval `[r, r')`. That hypothesis is a constraint on writers' linearization points relative to the observer's read — a coordination-layer obligation (extinction discipline, fair scheduling, bounded work — the coordination layer's named hypotheses), not a substrate guarantee.

## V2 — VerdictReaderSnapshot (THEOREM, lemma)

For a multi-read verdict — `p ≥ 2` constituent bounded-access reads composing one `Q`, whether `Observe_K` calls across types or the active-view read and per-home frontier descents of a `stale` enumeration (§8) — three conditions stand in a chain of *strict* implications, not in equivalence:

`[all p reads at one committed index Σ_r] ⟹ [no Q-affecting step linearizes between the first and last read] ⟹ [the verdict is sound about a single state].`

The middle condition — *no `Q`-affecting step between the reads* — is the weakest *sufficient* condition this note establishes, **not** a necessary one: the implication to soundness is genuinely *strict*, since a verdict may come out sound by other routes — `g` insensitive to the disturbed constituent, or `g`'s value coinciding with `Q` of some single state — even when a `Q`-affecting step does fall between the reads (the banking argument above proves only the sufficient direction, no `Q`-affecting step ⟹ verdict `= Q(Σ_{r₁})`, and offers nothing converse). Each implication's converse fails — the first because a non-`Q`-affecting step scatters the reads across distinct indices yet leaves soundness intact, the second because soundness survives when `g` discards the disturbed constituent — and the prose below exhibits a concrete witness for each, alongside the trace. The first — *all reads at one index* — is *strictly* stronger: a non-`Q`-affecting step falsifies it while preserving soundness. We single it out not because soundness needs it but because a reader-side critical section conveniently *supplies* it, and MIC clause 6 *adopts* it for safety — pinning all `p` reads to one index discharges the soundness requirement a fortiori, sparing the recognizer from having to classify which steps are `Q`-affecting. The one-index construction is *constructible* (hold the exclusion, take the `p` reads, release: they then all read one `Σ_r`) but *not automatic* from the per-type `Observe_K`, which pins each call to its own index and no further. The substrate neither provides nor forbids it.

## MIC — MinimalIsolationContract (DEF, definition)

A faithful realization of the substrate's consistency model must honour:

1. **Per-step atomicity (A0).** Each atomic transition is applied indivisibly; no observer reads a state strictly between `Σ_i` and `Σ_{i+1}`.
2. **Per-home allocation serialization (H0, H2).** For each `(home, subspace) (d, S)`, the frontier-read-and-deposit of any two `S`-allocations to `d` are mutually exclusive — securing same-home uniqueness (H2); chain contiguity (W1) holds regardless, model-intrinsic. Cross-`(d,S)` allocations need no coordination (H1). Document registration `K.σ` is the account-tier instance of this clause (the shared-frontier conditional, §4/H3).
3. **Commit-before-acknowledge (A7).** An operation's response is produced only at or after its linearization point.
4. **Per-call snapshot reads (A3, V0).** Each *single-bounded-access* read — an `Observe_K`, or BH4's `age` — is evaluated against a single committed state `Σ_k` (V0). The *several*-access reads — cross-type joins and `stale` — are clause 6's, not this clause's.
5. **Per-run critical section for contiguous runs (W2).** A definition's multi-atom content run holds exclusion on its `(d, s_C)` for the run's duration; no foreign content allocation to `d` interleaves.
6. **Per-verdict reader snapshot (V2).** A verdict composed of two or more bounded-access reads — several `Observe_K` calls, a cross-type join, or a `stale` enumeration — must pin all its constituent reads to one committed index, via a reader-side critical section against any interleaving writer step. This exclusion is *global*, not per-home (V2). A *single-bounded-access* verdict (V0) discharges this clause for free under clause 4.
7. **Per-coverage-class idem=⊤ de-duplication serialization (I1a, I4).** For each coverage class `[K]` of an `idem(K) = ⊤` type, the dedup-read of the *global* active subset `A_K` and the consequent deposit form **one atomic action**, pinned to the operation's linearization index — so an `Emit_K` that misses does so against its *own* deposit's pre-state, never a stale earlier state. Since the dedup-read of `A_K` is global, not per-home (ASN-0128 I1), this is a **non-per-home**, *per-coverage-class* serialization: orthogonal to clause 2 (which still governs the deposit's allocation freshness), and the one *operation*-level guarantee that resists the per-home thesis — *role*-distinct from the allocation clauses 2/5 and the reader-side clause 6. An `idem = ⊥` emit (no dedup) and any allocation discharge it trivially. Drop it and per-home MIC permits the duplicate; the atomic dedup-read-and-deposit is the delta that restores the *operative* `K`-surface-emittedness I1a's induction needs and so suppresses it (G2; §4 instance (i)).

## SAFE — SafetyUnderMIC (THEOREM, lemma)

Under MIC, (a) no reader observes a torn effect; (b) no *single operation's* effect is observed twice, and idempotent emission admits no duplicate *under clause 7* (per-home clauses 1–6 alone permit an `idem = ⊤` duplicate, §4 instance (i)) — while non-idempotent emission admits content-equal tuples *by design*, which MIC neither prevents nor intends to; (c) no writer collides with a concurrent writer's *allocation* — a sub-allocator emission `K.α`/`K.λ_sh`, or, under §4's shared-frontier conditional, a `K.σ` into an account's document allocator; and (d) no multi-read verdict straddles a write.

*Proof.* (a) *No torn effect.* Any single emission or nullification is one step; by clauses 1 and 4 the reader's read is single-state (A3) and lands before or after that step, never within (A4). A batch is not a single effect; its constituents are each whole, and clause 4 ensures each read is one canonical snapshot (A6) — fully structurally canonical, never corrupt (though, by §2, possibly mid-batch).

(b) *No duplicated effect — scoped to what is actually proved.* Two facts hold, and a third must be stated plainly so the guarantee is not overclaimed. *(i) Per-operation uniqueness.* Each state-changing operation is realized at one unique index (A1), so *its* effect appears exactly once in the order; no single operation is double-applied. *(ii) Idempotent collapse — under clause 7, and only then.* Under clause 7, I1a applies (G2; §4 instance (i)), so `A_K` holds at most one tuple per coverage class; resurrection-after-nullification is by design (W3, ASN-0128 I2), not a duplicate. Per-home clauses 1–6 alone do not place an `idem = ⊤` execution in I1a's scope — the both-miss interleaving breaks its induction and the duplicate stands (G2) — so the guarantee rests on clause 7, not per-home MIC. That same clause reduces two *concurrent* coverage-equal emissions into distinct homes to operation-level *non-confluence* rather than duplication: first-to-commit (ASN-0128 I4) fixes which home keeps the lone survivor (§4 instance (i)); absent clause 7 the dependence reaches *how many*, the both-miss interleaving leaving two. *(iii) But `idem(K) = ⊥` duplicates by design, and MIC does not prevent it.* Two `Emit_K` calls with identical `(F, G, K)` under `idem(K) = ⊥` produce *distinct* addresses, and *both* tuples appear in the active subset (ASN-0128 I5; ASN-0086 R2's consequence) — a reader observing `A_K` then sees two tuples of identical content. This is intended: a fresh non-idempotent emission is how the layer expresses a genuinely new instance, and no clause of MIC forbids it. In particular, commit-before-acknowledge (clause 3 / A7) does *not* suppress it: A7 fixes only that a response is produced at-or-after `lin(op)`; it neither detects nor cancels a *lost* acknowledgment, so a client that times out and retries a non-idempotent emission commits a second tuple, and A7 is indifferent to the fact. What collapses semantic repeats is idempotency (ii), not acknowledgment ordering. MIC's (b) guarantee is therefore exactly (i)+(ii). The reference-sharing principle — one permanent address, never a copy (ASN-0086) — governs *transclusion of content*, not two distinct link tuples that happen to carry equal endsets, and must not be invoked to claim more.

(c) *No allocation collision.* Two sub-allocator emissions `K.α`/`K.λ_sh` conflict only when into the same `(d, S)` (H1, H2); clause 2 serializes exactly those, so each reads a distinct frontier (H0) and deposits a fresh, unique address (H2), and clause 5 extends this to whole runs (W2). Writers into distinct `(d, S)` by H1 never collide and need no coordination. Document registration `K.σ` collides only among same-account creations and is covered identically by the account tier of clause 2 (§4/H3).

(d) *No verdict straddles a write.* The case split is by *access count* (§8: V0, V2). A *single-bounded-access* verdict — a single `Observe_K`, an `age` read of one home's frontier `f_d`, an empty-slice `stale` (`N = 0`, one `Observe_K(oper)`), or a single-type `targets_keyed` join (V0) — reads one canonical state by clause 4 (A3, A6, V0), the clause now covering every one-access read rather than `Observe_K` alone. A multi-read verdict — `p ≥ 2` accesses: a cross-type join over two or more types, or a non-empty `stale` enumeration (`N ≥ 1`, single- or multi-home) — under clause 6, has its `p` constituent reads pinned to one committed index `Σ_r` (V2), so it is a statement about one coexisting state and cannot manufacture, in the recognizer's own evaluation, the cross-index error V2's trace exhibits for reads that drift across indices. This is *soundness* about `Σ_r` (V0/V2); *durability* past `r` is V1's separate hypothesis, supplied by no MIC clause. ∎
